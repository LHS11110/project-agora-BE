# 탈퇴 계정의 개인정보 삭제

탈퇴 계정은 참조용 `user_id`와 `WITHDRAWN` 상태를 유지하고 닉네임을 **삭제된 계정**으로 바꿉니다. 원래 이메일·닉네임·태그·비밀번호 해시·OAuth 제공자/식별자·이메일/비밀번호 인증 시각은 남기지 않습니다. 이메일은 가짜 주소가 아니라 NULL이며, 역할은 일반 사용자로 초기화합니다. 기존 캔버스의 사용자 ID 참조와 생성/갱신 시각 같은 행 메타데이터는 유지합니다.

이메일 인증 증명, MFA 비밀키·복구 코드·인증 요청, 패스키·등록 요청, 사용자 세션과 프로필 이미지도 삭제합니다. 캔버스 이용 중인 경우 먼저 연결을 종료해야 탈퇴할 수 있는 정책은 유지합니다. 사용자가 작성한 캔버스 자체는 자동 삭제하지 않습니다.

동일한 이메일은 이메일 인증 후 다시 가입할 수 있으며 Google·네이버·카카오도 새 사용자 ID로 가입할 수 있습니다. 네이버 또는 이메일 미제공/미검증 OAuth는 기존 신규 가입 이메일 인증 절차를 적용합니다. 이전 계정의 권한·소유권·MFA·패스키를 복구하거나 승계하지 않습니다. 일반 이메일 로그인은 먼저 재가입해야 합니다.

## 저장소 변경

관리자 권한으로 `project-agora-DB/mssql/migrations/2026-11-01-user-erasure.sql`을 적용합니다(`TABLE_USERS=users`). 사용자 이메일을 NULL 허용으로 변경하고, NULL이 아닌 이메일만 고유성을 검사하는 필터 인덱스를 만듭니다. 활성/정지 계정에는 이메일을 필수로 유지합니다. 기존 WITHDRAWN 행도 개인정보와 관련 인증 행을 정리하며 활성 계정은 수정하지 않습니다. 새 설치용 init SQL에도 포함됩니다.

기존 탈퇴 계정의 프로필 파일은 같은 사용자 ID의 `canvas-resource/profiles/{id}.png`를 제거합니다. 앞으로의 탈퇴는 Spring의 UserErasureService가 DB 정리와 함께 파일을 제거합니다.

## 재가입과 토큰

이메일은 재사용할 수 있으므로 로그인 JWT에 `userId`를 포함하고 DB 사용자의 ID와 비교합니다. 이메일이 같아도 삭제 전 토큰으로 새 계정에 접근할 수 없습니다. MFA/패스키 발급 토큰에도 동일하게 적용하고, `/api/auth/me`의 body token도 검사합니다. 기존 userId 없는 로그인 토큰은 거절하므로 이 변경 배포 후에는 다시 로그인이 필요합니다. 인증 전에는 일반 계정의 비밀번호·Google·네이버·카카오 MFA 정책을 유지하며, 사용자 확인이 완료된 패스키는 추가 TOTP 없이 로그인합니다.

## 검증

UserErasureIntegrationTest는 이메일 계정 탈퇴, 관련 인증 데이터 정리, 같은 이메일 재가입, 예전 JWT의 거절과 새 토큰의 사용을 검증합니다. Google·네이버·카카오의 새 ID 재가입 및 기존 관리자 권한 미승계도 확인합니다. 실제 SQL Server에서 여러 NULL 이메일과 활성 이메일 고유성을 별도로 확인합니다.

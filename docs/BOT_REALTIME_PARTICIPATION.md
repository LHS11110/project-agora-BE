# 봇의 실시간 캔버스 참여

SDK 0.1.4부터 봇과 사용자 계정은 객체 채널과 참여 채널을 함께 연결한다. 기존 접속 토큰과 객체 채널이 발급한 연결 증명값으로 참여 채널을 연결하며 브라우저의 접속자 목록에도 표시된다. 서버의 캔버스 범위 및 객체 그룹 권한 검사는 그대로 적용된다.

- `canvas.peers`, `peer_id`, `presence_connected`: 현재 접속자와 참여 상태.
- `send_cursor`, `send_laser`, `set_editing`: 일반 사용자 화면과 같은 브로커 릴레이.
- `next_event`: 객체 커밋, 참여/퇴장, 커서/선택 영역, 레이저, 편집 상태, 채팅/댓글 등 허용된 이벤트 수신.
- 토큰 만료와 연결 장애: 두 채널을 새 인증과 연결 증명으로 복구. 저장 요청은 기존 영수증으로 확인하고 일시적 이벤트는 재전송하지 않는다.
- 커서는 참여자별 최신 위치를 합치며 객체 이벤트와 큐를 분리한다. 객체 이벤트 큐 초과는 `event_overflow`로 알리고 `items`는 최신 상태를 유지한다.

WebRTC 통화나 P2P 미디어 연결은 자동 생성하지 않는다. 커서 좌표는 SDK의 정규화된 캔버스 좌표를 사용한다. 실행 예제는 `sdk/python/examples/watch_canvas.py`에 있다.

## 검증 (2026-11-04)

Python SDK 테스트 24개와 프런트엔드 테스트 317개 통과. TLS WebSocket 테스트는 실제 소켓으로 두 채널의 연결 증명, 양방향 이벤트, 참여/퇴장, 연결 장애와 재인증을 확인한다.

운영 서버에 격리된 임시 계정·비공개 캔버스·봇을 생성해 양방향 커서, 레이저, 객체 편집 상태, 봇의 객체 수정/삭제, 다른 그룹의 객체 미전달을 확인했다. 실제 봇 접속 토큰 만료 후 참여 ID가 바뀌며 두 채널이 복구되고 후속 전송과 저장이 성공했다.

Chrome에서도 일반 사용자로 접속해 봇의 접속자 목록 표시와 커서 렌더링을 확인했다. Project Orchestra를 통해 문서와 wheel을 배포했고 HTTPS 다운로드 파일이 빌드한 wheel과 동일한 SHA-256임을 확인했다. 기존 사용자 데이터나 실행 VM은 변경하지 않았다.
